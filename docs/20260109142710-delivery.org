Goal: be able to deliver an item to any place on Danforth campus

Global map will be represented by a graph with nodes of waypoints and edges connecting the waypoints. The global planner will find the shortest path between the start and end waypoints. We can assume a constant cost /for now/.

There will be a global position estimate generated by an EKF that fuses the GPS position of the robot with the local estimate

The local estimate will be a drifting estimate generated by an EKF that fuses IMU data with wheel encoder data

MPPI will be used to stay along the local path between waypoints while avoiding obstacles

LiDAR will be used to detect obstacles and an RGBD camera will be used to identify what the obstacles are (e.g., person vs inanimate object)

The robot uses [[id:9b9c93e9-2b45-4526-8ae9-5ca80a95c172][Ackermann Steering]].

* Sensors
Sensors are required for /state estimation/, the problem of knowing where a robot is in the world and what the world around it looks like. The robot will keep track of a local state estimate using wheel encoders and an IMU, which is then refined globally using a (slower but less subject to drift) GPS. Understanding obstacles around the robot will be done using LiDAR (and maybe eventually a camera).

** Wheel Encoders
Wheel encoders count the number of times that a wheel has spun. This is one of the measurements that go into the overall localization of the robot.

I would tentatively suggest the [[https://www.digikey.com/en/products/detail/same-sky-formerly-cui-devices/AMT103-V/827016][AMT103-V]] encoders. This requires a rear-shaft on your motor, which I don't know if you have. If you don't, I think the best option is probably to buy a new motor that comes with an encoder pre-installed.

** IMU
An IMU gives the current acceleration, rotation, and magnetic heading of the robot. More expensive IMUs typically offer better performance in magnetic heading accuracy and calibration.

Any breakout board with a Bosch BNO055 should be more than adequate. From a quick search, either of these seem like fine options:
+ [[https://www.adafruit.com/product/2472][Adafruit]]
+ [[https://www.dfrobot.com/product-2142.html][DFRobot]]

This should be mounted near the center of the robot and attached securely so it doesn't vibrate too much.

** GPS
There are two options for how we might handle GPS. I would prefer to use RTK GPS if we can get it to work, as it provides a much higher accuracy. With that said, there are a few complications (below) that may or may not be difficult to overcome. Regular GPS is much less accurate (meters vs centimeters), but will be much closer to working out of the box. In all, I think we should try RTK GPS first until we know it doesn't work.

RTK GPS works by using a base station to provide centimeter-level accuracy. To avoid the hassle, cost, and LOS issues of setting up our own base station, we would use [[https://gpsweb3.modot.mo.gov/Login.aspx][MoDOT's NTRIP service]]. MoDOT provides their VRS GNSS system for free. The two closest base stations are 7 and 10 miles away from Danforth respectively, which is close enough to have accuracy of a few centimeters. Getting access to the network is free but requires some [[https://gpsweb3.modot.mo.gov/MODOT_RTK_GPS_USER_AGREEMENT.pdf][paperwork]] and a notary signature, but this is just a minor inconvenience.

We would then use a *[[https://www.sparkfun.com/sparkfun-gps-rtk2-board-zed-f9p-qwiic-gps-15136.html][ZED-F9P]] breakout board* from Sparkfun to connect to the base stations. This needs a separate antennna. Sparkfun has [[https://www.sparkfun.com/gnss/gnss-antennas.html][several options]], but the [[https://www.sparkfun.com/gnss-multi-band-magnetic-mount-antenna-5m-sma.html][ANN-MB-00]] seems best to me[fn:1] [fn:2]. Survey-grade antennas, like the [[https://www.sparkfun.com/gnss-multi-band-l1-l2-l5-surveying-antenna-tnc-spk6618h.html][SPK6618H]] are definitely more accurate and better at preventing "multi-path ghosts" but WashU's campus isn't urban enough for this to really matter.

If we don't decide to use RTK GPS, we could buy the cheaper [[https://www.sparkfun.com/sparkfun-gnss-l1-l5-breakout-neo-f10n-sma.html][NEO-F10N]] breakout board. This needs a compatible L1/L5 antenna, such as the [[https://www.sparkfun.com/gnss-l1-l5-multi-band-high-precision-antenna-5m-sma.html][ANN-MB1]] (see [fn:1]). GPS without RTK will have roughly meter-level accuracy, compared to centimeter-level accuracy with RTK. We could theoretically get away with this with good state-estimation if the price of the ZED-F9P is a concern.

*** Router
NTRIP requires an internet connection. WashU's campus WiFi is probably good enough that we can just get away with a standard [[https://www.amazon.com/GL-iNet-GL-SFT1200-Secure-Travel-Router/dp/B09N72FMH5][GL.iNET Travel Router]]. GL.iNET is a very solid brand as their routers are built on OpenWRT, which is infinitely more "hackable" than, e.g., Netgear or TL-Link routers, and have tools for dealing with enterprise WiFi connection (e.g., eduroam). If the robot disconnects for a few seconds, state estimation will still work with just the IMU and wheel encoders until it reconnects.

If we wanted to be independent of WashU's WiFi, GL.iNET has routers with 4G LTE connection (e.g., the [[https://www.amazon.com/GL-XE300-Industrial-T-Mobile-Supported-EC25-AFFA/dp/B08PYQL3V2][XE300]]). I wouldn't recommend that we start with this because of the increased price and hassle.

** LiDAR
A LiDAR is important for obstacle avoidance (i.e., not running people over). I'm fairly certain you guys already have a LiDAR (I think I remember Jaxon bought you guys one), so I won't recommend one unless you let me know that you don't have one.

I find it very unlikely that we would use a LiDAR for SLAM, as that is probably overkill and would be difficult to scale to the size of an entire campus.

* Dynamics
The dynamics are given by an extension of the [[id:19630a10-d863-4185-b071-4dddb7acb6c0][Bicycle Model]].

$$x = \begin{bmatrix} p_x \\ p_y \\ \theta \\ v \\ \omega \\ b_{\omega} \end{bmatrix}, \quad u = \begin{bmatrix} v_{cmd} \\ \delta \end{bmatrix}$$

$$\dot{x} = \begin{bmatrix} v \cos \theta \\ v \sin \theta \\ \omega \\ \frac{v_{cmd} - v}{\tau} \\ \frac{\left( \frac{v}{L} \tan \delta \right) - \omega}{\tau} \\ 0 \end{bmatrix}$$

for some motor constant $\tau$ and wheelbase $L$. Motor acceleration is essentially implemented as a [[id:83df04af-302f-4e73-9c06-f0a4fa46f17f][Low Pass Filter]]. The $b_{\omega}$ term is introduced to measure the bias of the IMU.

Euler is only stable for a DT of $< 2\tau \approx 0.02$ seconds, but MPPI and the EKF predict over longer horizons, which amplifies error and explodes the state. We therefore use the closed-form update, which is stable for any DT.

The car itself is a ~Vehicle~: its wheelbase, its steering limit, the two lags and the drive's acceleration limit. The defaults, ~SIM_VEHICLE~, were fitted to the Gazebo car. The real robot is shorter and steers less (0.363 m, 0.436 rad), so the controller takes all five as parameters (see [[*Parameters][Parameters]]). The vehicle is an argument of the jitted model, not a set of constants compiled into it: a new one, even at runtime, does not make jax compile the model or MPPI's step again. Leaving it out models the sim car. The EKF does that.

A vehicle the model cannot use is refused: the wheelbase must be positive and the steering limit below $\pi/2$, where $\tan \delta$ blows up (delivery-robo's arduino_bridge checks its own copies the same way). The lags and the acceleration limit must be positive because the closed form divides by them.

#+begin_src python :noweb yes :tangle ../src/autonomy/autonomy/utils/dynamics.py
import math
from typing import NamedTuple

import jax
import jax.numpy as jnp

STATE_DIMENSION = 6
INPUT_DIMENSION = 2


class Vehicle(NamedTuple):
    wheelbase: float = 0.5        # m, rear axle to front axle. The sim's is <wheel_base> in the robot description
    max_steer_rad: float = 0.6    # rad, the steering limit either way
    steer_tau: float = 0.545      # s, time constant of the steering
    drive_tau: float = 0.01       # s, time constant of the speed
    max_accel: float = 5.0        # m/s^2, the drive's acceleration limit


SIM_VEHICLE = Vehicle()
VEHICLE_PARAMS = SIM_VEHICLE._asdict()


def vehicle_param_problem(wheelbase, max_steer_rad, steer_tau, drive_tau, max_accel):
    """Return why this vehicle cannot be modelled, or None when it can."""
    for name, value in (('wheelbase', wheelbase), ('steer_tau', steer_tau),
                        ('drive_tau', drive_tau), ('max_accel', max_accel)):
        if not 0.0 < value < math.inf:
            return f'{name} must be positive, got {value}'
    if not 0.0 < max_steer_rad < math.pi / 2:
        return f'max_steer_rad must be in (0, pi/2) rad, got {max_steer_rad}'
    return None


@jax.jit
def dynamics_model(state: jnp.ndarray, inputs: jnp.ndarray, dt: float,
                   vehicle: Vehicle = SIM_VEHICLE) -> jnp.ndarray:
    x, y, theta, v, omega, b_omega = state
    v_cmd, delta_cmd = inputs
    wheelbase, max_steer, steer_tau, drive_tau, max_accel = vehicle
    # One division each per call, then products: MPPI runs this for every state of every rollout,
    # and dividing each of them by a parameter made its step 12 % slower than by a constant
    inv_drive_tau, inv_accel, inv_wheelbase = 1.0 / drive_tau, 1.0 / max_accel, 1.0 / wheelbase

    # Closed form acceleration
    v_gap = v_cmd - v
    accel = jnp.clip(v_gap * inv_drive_tau, -max_accel, max_accel)

    # Time spent at full acceleration before the
    # remaining gap is small enough
    t_clipped = jnp.clip(
        (jnp.abs(v_gap) - max_accel * drive_tau) * inv_accel, 0.0, dt)
    next_v = (v + accel * t_clipped
              + (v_gap - accel * t_clipped)
              ,* (1.0 - jnp.exp((t_clipped - dt) * inv_drive_tau)))

    # Recover the steering angle implied by the current yaw rate, holding the
    # sign through the zero crossing to avoid a singularity
    safe_v = jnp.where(jnp.abs(v) < 1e-5, jnp.sign(v + 1e-10) * 1e-5, v)
    current_delta = jnp.arctan((omega * wheelbase) / safe_v)

    delta_cmd = jnp.clip(delta_cmd, -max_steer, max_steer)
    # closed form
    next_delta = delta_cmd + (current_delta - delta_cmd) * jnp.exp(-dt / steer_tau)

    next_omega = (next_v * inv_wheelbase) * jnp.tan(next_delta)

    theta_mid = theta + 0.5 * next_omega * dt
    next_x = x + next_v * jnp.cos(theta_mid) * dt
    next_y = y + next_v * jnp.sin(theta_mid) * dt
    
    next_theta = theta + next_omega * dt
    next_theta = (next_theta + jnp.pi) % (2 * jnp.pi) - jnp.pi

    return jnp.array([next_x, next_y, next_theta, next_v, next_omega, b_omega])
#+end_src

def turning_radius_tdm41(vehicle, delta_cmd, v=1.0, seconds=8.0):
    """Radius of the circle the model settles on at v with delta_cmd held, from straight ahead."""
    state = jnp.array([0.0, 0.0, 0.0, v, 0.0, 0.0])
    for _ in range(round(seconds / 0.1)):
        state = dynamics_model(state, jnp.array([v, delta_cmd]), 0.1, vehicle)
    return v / float(state[4])


def test_full_lock_turns_on_the_vehicles_smallest_circle():
    assert turning_radius_tdm41(SIM_VEHICLE, 1.0) == pytest.approx(0.5 / math.tan(0.6), rel=1e-3)
    assert turning_radius_tdm41(ROBOT_TDM41, 1.0) == pytest.approx(0.36322 / math.tan(0.4363), rel=1e-3)
    # Within the limit the angle is the angle: the wheelbase alone sets the radius
    assert turning_radius_tdm41(ROBOT_TDM41, 0.2) == pytest.approx(0.36322 / math.tan(0.2), rel=1e-3)

*** GPS
The GPS gives us coordinates in degrees (i.e., latitude and longitude), but all of our other calculations are in meters with the origin centered on where the robot first turns on. Therefore, we wait for the first GPS reading to start state estimation and convert the lat/lon into meters. We use this to obtain an estimate of $p_x$ and $p_y$.

def process_gps_callback(self, msg: NavSatFix):
    lat_rad = math.radians(msg.latitude)
    lon_rad = math.radians(msg.longitude)
    timestamp = msg.header.stamp.sec + (msg.header.stamp.nanosec * 1e-9)

    if not self.received_first_gps:
        self.get_logger().info(
            f'GPS datum {msg.latitude:.8f}, {msg.longitude:.8f}: initializing state to (0,0)')

The conversion has to use the WGS84 ellipsoid, the shape GPS fixes are given on. It used to treat the Earth as a sphere with the equatorial radius. At our latitude (38.65° N) that is off by the ellipsoid's curvature: on the real ellipsoid a degree of latitude is 0.28 % shorter than on that sphere, and a degree of longitude 0.13 % longer. So 100 m north came out as 100.28 m and 100 m east as 99.87 m. In the sim that was a steady ~0.25 m EKF error at the end of a 190 m route (TDM-25).

We put the datum and the fix in Earth-centred, Earth-fixed (ECEF) coordinates on the ellipsoid and rotate their difference into east/north at the datum. The result is the datum's local tangent plane, the same model Gazebo's NavSat sensor uses (=washu.world= has =EARTH_WGS84= spherical coordinates). Projecting onto the plane shortens distances by less than a millimetre within 5 km. Height is ignored: a few metres of it move the horizontal position by less than 0.2 mm on campus. Over the planner's bounding box this agrees with pyproj's geodesics to within a micrometre. The old sphere was off by up to 28 cm per 100 m. In the sim, at rest at the end of the same 190 m route, the EKF is now 2 mm from ground truth instead of 0.25 m.

The =odom= frame is therefore true east/north metres from the datum. The planner's =map= is the UTM zone 15N grid, which differs from it in two ways:
- *Grid convergence*: 1.685° here. =gps_datum_tf= in delivery-robo puts it in the yaw of map→odom.
- *UTM point scale*: 1.00028 here (0.9996 at the central meridian, 93° W). A point 100 m from the datum is 100.028 m away in =map=, so 2.8 cm per 100 m are left over after the rigid map→odom. No rigid transform can absorb a scale.

The convergence also changes by 0.002° across the campus (about 1 cm over 300 m), which is likewise left over.

#+begin_src python :tangle ../src/autonomy/autonomy/utils/latlon2meters.py
import math

# WGS84, the ellipsoid GPS fixes (and Gazebo's NavSat sensor) use
WGS84_A = 6378137.0                   # semi-major axis [m]
WGS84_F = 1.0 / 298.257223563         # flattening
WGS84_E2 = WGS84_F * (2.0 - WGS84_F)  # first eccentricity squared

def geodetic_to_ecef(lat_rad, lon_rad):
    """ECEF position [m] of a point on the WGS84 ellipsoid (height 0)."""
    sin_lat = math.sin(lat_rad)
    cos_lat = math.cos(lat_rad)
    n = WGS84_A / math.sqrt(1.0 - WGS84_E2 * sin_lat * sin_lat)  # prime-vertical radius of curvature
    return (n * cos_lat * math.cos(lon_rad),
            n * cos_lat * math.sin(lon_rad),
            n * (1.0 - WGS84_E2) * sin_lat)

def latlon2meters(lon_rad, lat_rad, origin_lon, origin_lat):
    """East (x) and north (y) [m] of a fix from the origin, in the origin's local tangent plane."""
    x0, y0, z0 = geodetic_to_ecef(origin_lat, origin_lon)
    x1, y1, z1 = geodetic_to_ecef(lat_rad, lon_rad)
    dx, dy, dz = x1 - x0, y1 - y0, z1 - z0

    sin_lat, cos_lat = math.sin(origin_lat), math.cos(origin_lat)
    sin_lon, cos_lon = math.sin(origin_lon), math.cos(origin_lon)
    x = -sin_lon * dx + cos_lon * dy
    y = -sin_lat * cos_lon * dx - sin_lat * sin_lon * dy + cos_lat * dz

    return x, y
#+end_src

    u = path_node_ids[i]
    v = path_node_ids[i + 1]

    edge_data = self.G_projected.get_edge_data(u, v)[0]

    if 'geometry' in edge_data:
        # Extract the coordinates from the Shapely LineString
        xs, ys = edge_data['geometry'].xy
        points = list(zip(xs, ys))
    else:
        # Subdivide straight lines so interpolation doesn't bleed the heading!
        x0, y0 = self.G_projected.nodes[u]['x'], self.G_projected.nodes[u]['y']
        x1, y1 = self.G_projected.nodes[v]['x'], self.G_projected.nodes[v]['y']
        
        dist = math.hypot(x1 - x0, y1 - y0)
        # Generate a point every 0.25 meters
        num_points = max(int(dist / 0.25), 2) 
        
        xs = np.linspace(x0, x1, num_points)
        ys = np.linspace(y0, y1, num_points)
        points = list(zip(xs, ys))

    # Drop the overlapping node at intersections to prevent atan2(0,0)
    if all_points and points:
        dist_to_prev = math.hypot(points[0][0] - all_points[-1][0], points[0][1] - all_points[-1][1])
        if dist_to_prev < 0.01:
            points = points[1:]

    all_points.extend(points)

# Convert the points to the local metric frame and append to the path
for i, (pt_x, pt_y) in enumerate(all_points):
    pose = PoseStamped()
    pose.header = dense_path.header

    # Translate from UTM back to local Gazebo 'map' frame

    pose.pose.orientation.y = 0.0

** Boundary Map
The planner knows the sidewalks only as a graph of centre lines. Obstacle avoidance needs the same sidewalks as an area, so that a local planner can leave the centre line without leaving the pavement. This script rasterises the graph into an occupancy map. The graph comes from the planner's own [[*Initialize Graph][_initialize_graph]], so the map has the same bounding box, filter, and origin as the paths that the planner returns. The image is in the =map= frame, in the format that the Nav2 =map_server= reads.

            xs = (graph.nodes[u]['x'], graph.nodes[v]['x'])
            ys = (graph.nodes[u]['y'], graph.nodes[v]['y'])
        polylines.append(np.column_stack((xs, ys)) - np.asarray(origin))
    return polylines

def rasterize(polylines, half_width, resolution, margin):
    """Mark the cells within half_width of any polyline as free.

    Returns the mask, with row 0 in the south, and the map-frame position of
    its south-west corner.
    """
    points = np.vstack(polylines)
    corner = points.min(axis=0) - half_width - margin
    extent = points.max(axis=0) + half_width + margin - corner
    width, height = np.ceil(extent / resolution).astype(int)
    free = np.zeros((height, width), dtype=bool)

    for polyline in polylines:
        for a, b in zip(polyline[:-1], polyline[1:]):
            # Only the cells around this segment can be within reach of it
            lo = np.floor((np.minimum(a, b) - half_width - corner) / resolution).astype(int)
            hi = np.ceil((np.maximum(a, b) + half_width - corner) / resolution).astype(int) + 1
            lo = np.maximum(lo, 0)
            hi = np.minimum(hi, (width, height))
            xs = corner[0] + (np.arange(lo[0], hi[0]) + 0.5) * resolution
            ys = corner[1] + (np.arange(lo[1], hi[1]) + 0.5) * resolution
            px, py = np.meshgrid(xs, ys)

            # Distance from each cell centre to the closest point of the segment
            d = b - a
            length2 = d @ d
            t = 0.0
            if length2 > 0.0:
                t = np.clip(((px - a[0]) * d[0] + (py - a[1]) * d[1]) / length2, 0.0, 1.0)
            dist2 = (px - a[0] - t * d[0])**2 + (py - a[1] - t * d[1])**2
            free[lo[1]:hi[1], lo[0]:hi[0]] |= dist2 <= half_width**2

    return free, corner

def write_png(path, pixels):
    """Write an 8-bit greyscale image. PNG keeps a two-colour map small."""
    height, width = pixels.shape

    def chunk(tag, data):
        return (struct.pack('>I', len(data)) + tag + data
                + struct.pack('>I', zlib.crc32(tag + data)))

    # Each row starts with a filter byte; 0 means the row is stored as it is
    rows = b''.join(b'\x00' + row.tobytes() for row in pixels)
    with open(path, 'wb') as f:
        f.write(b'\x89PNG\r\n\x1a\n')
        f.write(chunk(b'IHDR', struct.pack('>IIBBBBB', width, height, 8, 0, 0, 0, 0)))
        f.write(chunk(b'IDAT', zlib.compress(rows, 9)))
        f.write(chunk(b'IEND', b''))

** Thread Limits
XLA and OpenBLAS size their thread pools once, when jax and numpy first load, so these lines come before every other import. Further down the file was too late: =autonomy.utils.dynamics= imports jax, =mppi_step= builds a jax array at import (which starts the XLA backend and parses =XLA_FLAGS=), and the ROS message modules import numpy. The old settings sat below those imports and never took effect.

- ~--xla_cpu_multi_thread_eigen=false~ keeps XLA's Eigen-backed ops (matrix products) on one thread.
- =PJRT_NPROC= sizes XLA's CPU thread pools, which otherwise get one thread per core.
- =OPENBLAS_NUM_THREADS= caps numpy's BLAS pool. The pip OpenBLAS on the Pi starts one thread per core as numpy loads. Nix's OpenBLAS is built with OpenMP and reads =OMP_NUM_THREADS= instead, so both are set.

The MPPI step is effectively single-threaded anyway. On the laptop it takes about 40 ms with 12 pool threads or 2, so the limits cost nothing: they only stop jax from claiming every core next to the EKF and Nav2. =setdefault= leaves a value that is already in the environment alone, so the shell or launch file can override them, e.g. ~PJRT_NPROC=4 ros2 run autonomy controller~. The old ~intra_op_parallelism_threads=2~ was a TensorFlow session option. XLA ignored it without complaint.

** Action
A path is followed until the robot is within the goal tolerances of its last pose. Then the goal succeeds with =success= true. Only the newest goal is ever open. A goal that arrives while another is running takes over the path, and the replaced goal finishes at once, *aborted* with =success= false. ROS 2 actions have no "preempted" status, and Nav2's own servers abort a goal they preempt, so clients get the same answer here. =local_planner= replans about once a second; before this change every one of those goals stayed open until the robot arrived. An empty path is an order to stop. The controller zeroes the command at once and the empty goal itself succeeds.

def process_state_callback(self, odom_msg: Odometry):
    try:
        t = self.tf_buffer.lookup_transform('map', odom_msg.header.frame_id, rclpy.time.Time())
        q = t.transform.rotation
        self._map_to_odom = (
            t.transform.translation.x,
            t.transform.translation.y,
            np.arctan2(2.0 * (q.w * q.z + q.x * q.y), 1.0 - 2.0 * (q.y**2 + q.z**2)),
        )
    except TransformException as ex:
        if self._map_to_odom is None:
            self.get_logger().warning(
                f'No map->{odom_msg.header.frame_id} transform yet: {ex}', throttle_duration_sec=2.0)
            return None
    map_x, map_y, map_yaw = self._map_to_odom
    self._odom_frame = odom_msg.header.frame_id

    # Extract Position and Yaw (theta) in Map frame
    p = odom_msg.pose.pose.position
    q = odom_msg.pose.pose.orientation
    c, s = np.cos(map_yaw), np.sin(map_yaw)
    x = map_x + c * p.x - s * p.y
    y = map_y + s * p.x + c * p.y
    theta = map_yaw + np.arctan2(2.0 * (q.w * q.z + q.x * q.y), 1.0 - 2.0 * (q.y**2 + q.z**2))

    v = odom_msg.twist.twist.linear.x
    omega = odom_msg.twist.twist.angular.z

    # TODO: get this somehow
    b_omega = 0

    self.current_state = np.array([x, y, theta, v, omega, b_omega])

def process_costmap_callback(self, msg: OccupancyGrid):
    costmap = Costmap.from_msg(msg)
    arrival = self.get_clock().now()
    # The speed limit goes by every obstacle cell of the last OBSTACLE_MEMORY seconds
    recent = [(t, c) for t, c in self._recent_costmaps
              if 0.0 <= (arrival - t).nanoseconds * 1e-9 <= OBSTACLE_MEMORY]
    recent.append((arrival, costmap))
    self._recent_costmaps = recent
    self.costmap_remembered = remembered_costmap([c for _, c in recent])
    self.costmap, self.costmap_arrival = costmap, arrival

With =use_costmap= true and no costmap at all (Nav2 not running), the robot only ever crawls. Set it to false to follow paths without Nav2.

They can be set at launch (e.g. ~max_speed:=0.8~; write doubles, ~1.0~ not ~1~) or changed while running with ~ros2 param set /controller_server max_speed 0.8~. A value that fails the checks below is refused: at startup the node will not start, and at runtime the set is rejected with the reason. Speeds are checked against the range MPPI is tuned for. Up to 1.5 m/s its 5 s rollouts also stay inside the costmap window ([[*Obstacle Cost][Obstacle Cost]]). MPPI samples speeds between =min_speed= and the tick's target speed, the same bounds the command is clipped to. =min_speed= may not be positive, or the stop command (zero) would be clipped into motion.

The car MPPI drives in its rollouts has parameters too (the =Vehicle= of [[*Dynamics][Dynamics]]). Their defaults are the sim car's, so the sim sets none of them:

| Parameter       | Default | Meaning                                                                                      |
|-----------------+---------+----------------------------------------------------------------------------------------------|
| =wheelbase=     |     0.5 | m. Rear axle to front axle: MPPI's model, and the yaw rate sent for its steering angle.      |
| =max_steer_rad= |     0.6 | rad. The steering limit either way. MPPI samples within it and the command is clipped to it. |
| =steer_tau=     |   0.545 | s. Time constant of the steering.                                                            |
| =drive_tau=     |    0.01 | s. Time constant of the speed.                                                               |
| =max_accel=     |     5.0 | m/s². The drive's acceleration limit.                                                        |

They used to be constants of the sim car. On the robot, MPPI then believed it could turn on a 0.73 m radius where the robot manages 0.78 m. Curvature still came out right below that, because the arduino_bridge turns the yaw rate back into an angle with the real wheelbase. Any model angle above 0.570 rad was clipped at the robot's 0.4363 rad, though, and the robot turned up to 6.6 % wider than MPPI predicted. =wheelbase= and =max_steer_rad= are named like the values delivery-robo's hardware.yaml shares between its nodes, so the robot's one measured wheelbase and steering limit reach this controller and the bridge alike. Nobody has measured the robot's lags yet. Until someone does, it keeps the sim's.

The vehicle is passed to the jitted step as an argument, not compiled in. A new value at runtime does not compile it again, as long as it is plain floats every time (=vehicle_from=). In the sim, keep the defaults: the Gazebo car stays 0.5 m and 0.6 rad whatever the controller believes.

def publish_command(self, u):
    v_cmd, delta = u

    v_cmd_float = float(v_cmd)
    delta_float = float(delta)

    v_cmd_float = max(min(v_cmd_float, self.max_speed), self.min_speed)
    delta_clipped = np.clip(delta_float, -self.max_steer_rad, self.max_steer_rad)
    omega = (v_cmd_float / self.wheelbase) * np.tan(delta_clipped)

    cmd_vel = Twist()

    cmd_vel.linear.x = v_cmd_float
    cmd_vel.angular.z = omega

    self.cmd_pub.publish(cmd_vel)

        return FollowPath.Result(success=True)

    self.get_logger().info('Received a new path to follow!')
    self.current_path = path
    self.progress_idx = 0
    done = self._goal_done = Future()
    self.active_goal = True

    # Wait without blocking the single-threaded executor
    reached = await done

    if reached:
        goal_handle.succeed()
    else:
        goal_handle.abort()
    return FollowPath.Result(success=reached)

def _finish_goal(self, reached):
    done, self._goal_done = self._goal_done, None
    if done is not None and not done.done():
        done.set_result(reached)

*** Obstacle Speed Limit
MPPI only tracks the path. It knows nothing about obstacles. Nav2's local planner routes the path round whatever the costmap shows, but it replans only twice a second, and a 2D lidar sees the near face of a box long before its sides. In TDM-25's sim runs the paths swung back towards the centreline through the part of a box nobody had seen yet, and at 1.5 m/s the robot passed a box in the middle of a corridor 0.00-0.24 m away. So every tick the controller checks the path ahead against the costmap. When the path would take it close to something, it slows down, or stops.

The obstacles are cells of 99 (inscribed) and 100 (lethal). Nav2 marks a cell 99 when a robot centred there would have its footprint's inscribed circle (radius 0.32 m) touching an obstacle. The distance from the robot's centre to the nearest such cell is then about the gap between the side of the footprint and the obstacle. At the front the real gap is ~0.08 m less, at a corner up to 0.19 m less. That way the costmap brings the footprint along, and the controller needs no copy of it. Distances are measured to the nearest edge of a cell, not its centre, because a centre anywhere in the cell collides. On a 0.1 m grid that keeps the measured gap from coming out larger than the real one, which matters in a gap only a little wider than the robot.

Not every such cell counts. In a 3 m corridor the walls are always about 1.2 m from the robot, closer than =slow_distance=, so measuring to them would keep the robot at half speed for good. The cells that count are the ones the path ahead (the next =clearance_lookahead= metres) passes within =stop_distance= of, and only if following the path brings the robot closer to them. The clearance is the distance from the robot to the nearest of these. The speed limit is =max_speed= beyond =slow_distance=, then falls linearly towards zero at =stop_distance=, but never below =obstacle_creep_speed=. At =stop_distance= and inside it, it is zero. At zero the controller sends zero and keeps the goal open. It drives on once the costmap clears, or once local_planner sends a path that keeps =stop_distance=. The "closer" condition stops the robot from locking itself in place. Something behind the robot that the path leads away from does not count.

Inside =stop_distance= the rule is stricter (TDM-42): there the robot may only move away. The path has to have it at least =CLOSER_BY= further from the nearest cell =ESCAPE_DISTANCE= (0.3 m) along, and never closer on the way. Otherwise the clearance is the robot's own distance to that cell, and the limit is zero. A path that does lead out allows =obstacle_creep_speed= at most. Before this rule, a path running beside a box counted for nothing: it brought the robot no closer to the cells level with it, and the cells further along were beyond =stop_distance=. In 4 of TDM-40's 6 runs the robot crept along a box that way, 0.17-0.19 m from it. 0.3 m is where a turn of radius 1.0 m that starts parallel to the obstacle has taken the robot 0.045 m away from it.

The speed limit goes by every obstacle cell in the last =OBSTACLE_MEMORY= (1 s) of costmaps, not only the latest. The cells at a box's corner came and went between updates as the lidar's hits and the EKF pose jittered. In one TDM-42 run the robot's clearance read 0.19, 0.26, 0.17, 0.22 and 0.14 m in successive costmaps while it stood or crept beside the box. Every update without those cells let it creep a few centimetres closer, to 0.170 m by ground truth. The grids are combined cell by cell, and the highest value wins. Nav2's rolling window moves in whole cells, so they line up by shifting. A cleared obstacle holds the robot up to a second longer. MPPI's obstacle cost still uses the latest costmap.

The floor is there because a speed proportional to the distance left never gets the robot to =stop_distance=. In the sim it inched along at 0.01 m/s and never counted as stopped. The first fix counted any limit under 0.05 m/s as a stop, but that moved the stop line out. With the robot's values (=max_speed= 1.0, =stop_distance= 0.2) the ramp passes 0.05 m/s at 0.2 + 0.05 × 1.8 / 1.0 = 0.29 m. Smac's path through the gap beside a box centred in a 3 m corridor runs about 0.2 m from the box's inscribed band, so the robot stopped there in 3 of 4 runs (TDM-34). With the floor it keeps moving, at a speed the drive can track, until it is at =stop_distance=. From 0.15 m/s it rolls only a few centimetres after the zero command.

The robot therefore never drives through a gap narrower than its width plus twice =stop_distance= (0.63 + 0.7 m with the defaults). It waits in front of it instead. A box in the middle of a 3 m corridor leaves two 1.2 m gaps, so the robot stops there. Squeezing past would leave at most 0.27 m on each side. With the robot's 0.2 m that is 0.07 m to spare on each side, and less than the costmap's own noise. Against ground truth (TDM-42, seven runs, robot within 0.45 m of the box) the distance to the nearest inscribed cell's edge came out 0.02-0.07 m short of the footprint's real clearance, as a median per run. In single updates it ranged from 0.11 m short to 0.17 m over. It comes out over when a corner of the footprint swings in on a turn, which the centre does not see.

Measured in the sim (TDM-32, TDM-25's route with a 0.6 m box, ground truth):
- No box: not slowed once in 190 m.
- Box in the middle of the corridor: slows from about 2 m out and stops 0.24-0.29 m from it, goal still open. Once the box is removed it drives on within half a second.
- Box 0.45 m off-centre: slows to 0.64 m/s while the path still runs through the box's unseen side, then passes 0.49 m away. TDM-25 measured 0.36 m without the speed limit.
- Box in the middle with =stop_distance= 0.2: squeezes through at 0.3-0.4 m/s, 0.24 m from the box, with three short stops in the gap.
The check takes under 0.2 ms a tick.

Measured again with the floor (TDM-40, same route and box, the robot's values: =max_speed= 1.0, =min_speed= 0, =stop_distance= 0.2):
- Box in the middle, 6 runs: creeps at 0.15 m/s from about 0.4 m and stops where it measures 0.19-0.20 m (0.18-0.26 m by ground truth). In 4 runs a new path then ran beside the box rather than towards it, so the box no longer counted, and the robot crept on (1 cm to 0.44 m) until the next path stopped it again. It came to rest 0.178-0.195 m from the box. With the 0.05 m/s cut-off it stopped 0.21-0.26 m away (TDM-34). It never touched the box and never got through. Once the robot is that close, local_planner's paths from where it stands pass the box 0.08-0.16 m from its inscribed band, so none of them keeps =stop_distance=.
- No box: not slowed once. Box 0.45 m off-centre: passes 0.46 m away without slowing.

Measured with the rule inside =stop_distance= and the 1 s memory (TDM-42, same route, box and values; local_planner's paths are no longer smoothed, see delivery-robo =nav2_local.yaml=):
- Box in the middle, 8 runs, no contact. 3 passed, all through the south gap, 0.189-0.215 m from the box at the closest. Each time that was on the turn back behind it, where the rear corner swings in and the centre's distance does not show it. 5 stopped, all at the north gap, 0.196-0.209 m from the box, and drove on once it was removed. The box stands 5° askew to the corridor. On the north side its widest point is the near corner, so a robot still swinging out runs into the stop line there. On the south side the widest point is the far corner, which leaves more room to get out in time.
- Without the memory (4 runs) one robot crept from 0.186 m to 0.170 m while the corner's cells flickered. With it the closest stop was 0.196 m.
- No box: not slowed once, mean 0.99 m/s. Box 0.45 m off-centre: passes 0.47 m away without slowing.

Without a usable costmap the speed is capped at =crawl_speed=: none has arrived yet, the last one is older than =costmap_timeout=, or it is in a frame the controller cannot place. A stale costmap still stops the robot for what it shows. The path and the robot state are in map, while Nav2's costmap is in odom (=nav2_local.yaml=). The points are moved into the costmap's frame with the cached map->odom. A costmap in map is used as it is.

The geometry has no ROS in it, so it lives in a module of its own with plain tests. The MPPI obstacle cost can reuse =Costmap= and =to_frame=.

#+begin_src python :tangle ../src/autonomy/autonomy/utils/costmap_speed.py
"""Speed limit from Nav2's costmap: slow down near obstacles on the path ahead, stop short of them."""
import math
from typing import NamedTuple

import numpy as np

# Defaults, under the names the controller declares them as parameters
GOVERNOR_PARAMS = {
    'use_costmap': True,
    'slow_distance': 2.0,          # m: full speed beyond this clearance
    'stop_distance': 0.35,         # m: zero at or below it
    'obstacle_creep_speed': 0.15,  # m/s: the obstacle limit's floor short of stop_distance
    'clearance_lookahead': 3.0,    # m of path checked
    'costmap_timeout': 1.0,        # s: older than this counts as no costmap
    'crawl_speed': 0.3,            # m/s: the cap without a usable costmap
    'goal_decel': 0.8,             # m/s^2: braking for the end of the path (End of Path)
    'goal_creep_speed': 0.15,      # m/s: the taper never goes below this
}

# Nav2's OccupancyGrid: 100 lethal, 99 inscribed, 1-98 inflation, 0 free, -1 unknown
INSCRIBED = 99

# Spacing of the points checked along the path, about one costmap cell
PATH_STEP = 0.1

# How much closer (m) the path has to bring the robot to a cell for that cell to count
CLOSER_BY = 0.01

# Within stop_distance already, the path must have the robot at least CLOSER_BY further from the
# nearest cell this far (m) along it, or the robot stops
ESCAPE_DISTANCE = 0.3

# s: an obstacle cell in any costmap this recent still counts
OBSTACLE_MEMORY = 1.0


class Costmap(NamedTuple):
    cells: np.ndarray   # (height, width) int8; row = y, column = x
    resolution: float   # m per cell
    origin: tuple       # (x, y) of the outer corner of cell [0, 0], in `frame`
    frame: str

    @classmethod
    def from_msg(cls, msg):
        """From a nav_msgs/OccupancyGrid. Nav2 never rotates the origin, so its orientation is ignored."""
        info = msg.info
        cells = np.asarray(msg.data, dtype=np.int8).reshape(info.height, info.width)
        return cls(cells, info.resolution, (info.origin.position.x, info.origin.position.y),
                   msg.header.frame_id)


def remembered_costmap(costmaps):
    """The newest of `costmaps` (oldest first), each cell raised to the highest value any of them
    holds there. Nav2's rolling window moves in whole cells, so the grids line up by shifting.
    Grids in another frame or at another resolution are skipped."""
    newest = costmaps[-1]
    cells = newest.cells.copy()
    height, width = cells.shape
    res = newest.resolution
    for old in costmaps[:-1]:
        if old.frame != newest.frame or old.resolution != res:
            continue
        # old cell [r, c] is newest cell [r + dr, c + dc]
        dc = round((old.origin[0] - newest.origin[0]) / res)
        dr = round((old.origin[1] - newest.origin[1]) / res)
        r0, r1 = max(dr, 0), min(dr + old.cells.shape[0], height)
        c0, c1 = max(dc, 0), min(dc + old.cells.shape[1], width)
        if r0 < r1 and c0 < c1:
            np.maximum(cells[r0:r1, c0:c1], old.cells[r0 - dr:r1 - dr, c0 - dc:c1 - dc],
                       out=cells[r0:r1, c0:c1])
    return newest._replace(cells=cells)


def governor_param_problem(use_costmap, slow_distance, stop_distance, obstacle_creep_speed,
                           clearance_lookahead, costmap_timeout, crawl_speed, goal_decel,
                           goal_creep_speed):
    """Return why these settings are unusable, or None when they are fine."""
    if not obstacle_creep_speed > 0.0:
        return (f'obstacle_creep_speed must be positive (or the robot never reaches stop_distance), '
                f'got {obstacle_creep_speed}')
    if not goal_decel > 0.0:
        return f'goal_decel must be positive, got {goal_decel}'
    if not goal_creep_speed > 0.0:
        return f'goal_creep_speed must be positive (or the robot never reaches the goal), got {goal_creep_speed}'
    if not stop_distance >= 0.0:
        return f'stop_distance must be >= 0 m, got {stop_distance}'
    if not slow_distance > stop_distance:
        return f'slow_distance must be greater than stop_distance ({stop_distance} m), got {slow_distance}'
    if not clearance_lookahead > 0.0:
        return f'clearance_lookahead must be positive, got {clearance_lookahead}'
    if not costmap_timeout > 0.0:
        return f'costmap_timeout must be positive, got {costmap_timeout}'
    if not crawl_speed >= 0.0:
        return f'crawl_speed must be >= 0 m/s, got {crawl_speed}'
    return None


def speed_for_clearance(clearance, max_speed, slow_distance, stop_distance, creep_speed):
    """max_speed beyond slow_distance, then linearly down towards 0 at stop_distance but never
    below creep_speed (nor above max_speed); 0 at or below stop_distance."""
    if clearance <= stop_distance:
        return 0.0
    if clearance >= slow_distance:
        return float(max_speed)
    ramp = max_speed * (clearance - stop_distance) / (slow_distance - stop_distance)
    return float(min(max(ramp, creep_speed), max_speed))


def to_frame(points, frame_pose):
    """Map-frame points (N, 2) into a frame whose pose in map is (x, y, yaw)."""
    x, y, yaw = frame_pose
    c, s = math.cos(yaw), math.sin(yaw)
    d = np.asarray(points, dtype=float) - (x, y)
    return np.column_stack((c * d[:, 0] + s * d[:, 1], c * d[:, 1] - s * d[:, 0]))


def path_progress(position, path_xy, path_s, start_idx):
    """Arc length along the path of `position`'s projection onto it. Like get_local_reference,
    the projection is searched from `start_idx`, the progress so far."""
    position = np.asarray(position, dtype=float)[:2]
    end = min(len(path_xy), start_idx + 50)
    i = start_idx + int(np.argmin(np.linalg.norm(path_xy[start_idx:end] - position, axis=1)))
    best, s0 = np.linalg.norm(path_xy[i] - position), float(path_s[i])
    for j in (i - 1, i):   # the segments either side of the closest point
        if 0 <= j < len(path_xy) - 1:
            a, v = path_xy[j], path_xy[j + 1] - path_xy[j]
            seg2 = float(v @ v)
            if seg2 > 0.0:
                t = min(max(float((position - a) @ v) / seg2, 0.0), 1.0)
                d = np.linalg.norm(a + t * v - position)
                if d < best:
                    best, s0 = d, float(path_s[j] + t * math.sqrt(seg2))
    return s0


def path_ahead(position, path_xy, path_s, start_idx, length, step=PATH_STEP):
    """`position`, then points every `step` m along the path, from the position's projection
    onto the path to `length` m further on (or the end of the path)."""
    position = np.asarray(position, dtype=float)[:2]
    s0 = path_progress(position, path_xy, path_s, start_idx)
    s1 = min(s0 + length, path_s[-1])
    s = np.append(np.arange(s0, s1, step), s1)
    ahead = np.column_stack((np.interp(s, path_s, path_xy[:, 0]), np.interp(s, path_s, path_xy[:, 1])))
    return np.vstack((position, ahead))


def cell_distances(costmap, points, reach):
    """(cells, points) distances from each point to the nearest edge of every inscribed or lethal
    cell within `reach` of some point, or None when there is none. All in the costmap's frame."""
    points = np.asarray(points, dtype=float).reshape(-1, 2)
    res = costmap.resolution
    ox, oy = costmap.origin
    height, width = costmap.cells.shape
    lo = points.min(axis=0) - reach
    hi = points.max(axis=0) + reach
    c0, c1 = max(int((lo[0] - ox) // res), 0), min(int((hi[0] - ox) // res) + 1, width)
    r0, r1 = max(int((lo[1] - oy) // res), 0), min(int((hi[1] - oy) // res) + 1, height)
    if c0 >= c1 or r0 >= r1:
        return None
    rows, cols = np.nonzero(costmap.cells[r0:r1, c0:c1] >= INSCRIBED)
    if rows.size == 0:
        return None
    centres = np.column_stack((ox + (cols + c0 + 0.5) * res, oy + (rows + r0 + 0.5) * res))
    # To the nearest point of each cell, not its centre
    gap = np.maximum(np.abs(centres[:, None, :] - points[None, :, :]) - res / 2, 0.0)
    return np.hypot(gap[..., 0], gap[..., 1])


def obstacle_clearance(costmap, points, stop_distance):
    """Distance from points[0] (the robot) to the nearest inscribed or lethal cell that the path
    points[1:] passes within stop_distance of and brings the robot closer to. A robot within
    stop_distance of a cell already gets its distance to the nearest cell, unless the path leads
    straight out. All in the costmap's frame. inf when no cell counts."""
    # Only cells within stop_distance of a point can count (+ CLOSER_BY for the way out)
    dist = cell_distances(costmap, points, stop_distance + CLOSER_BY)
    if dist is None:
        return math.inf
    now = dist[:, 0]
    ahead = dist[:, 1:].min(axis=1) if len(points) > 1 else now
    clearance = float(now.min())
    if clearance <= stop_distance:
        # Out means further from every cell ESCAPE_DISTANCE along, and never closer on the way
        escape = dist[:, min(1 + round(ESCAPE_DISTANCE / PATH_STEP), len(points) - 1)].min()
        out = escape >= clearance + CLOSER_BY and ahead.min() >= clearance - CLOSER_BY
        return math.inf if out else clearance
    counts = (ahead < stop_distance) & (ahead < now - CLOSER_BY)
    return float(now[counts].min()) if counts.any() else math.inf


def robot_clearance(costmap, position, reach):
    """Distance from `position` to the nearest inscribed or lethal cell, inf beyond `reach`."""
    dist = cell_distances(costmap, position, reach)
    return math.inf if dist is None else float(dist.min())


def speed_limit(costmap, age, points, costmap_pose, max_speed, slow_distance, stop_distance,
                creep_speed, costmap_timeout, crawl_speed):
    """The speed limit for a robot at points[0] about to follow points[1:] (map frame).

    costmap: a Costmap or None; age: s since it arrived; costmap_pose: its frame's pose in map
    as (x, y, yaw), or None if unknown. Returns (limit m/s, clearance m or None, status), status
    one of 'clear', 'slow', 'stop' (fresh costmap) or 'missing', 'unplaced', 'stale' (capped at
    crawl_speed; a stale costmap still stops the robot for what it shows)."""
    crawl = min(crawl_speed, max_speed)
    if costmap is None:
        return crawl, None, 'missing'
    if costmap_pose is None:
        return crawl, None, 'unplaced'
    points = to_frame(points, costmap_pose)
    clearance = obstacle_clearance(costmap, points, stop_distance)
    limit = speed_for_clearance(clearance, max_speed, slow_distance, stop_distance, creep_speed)
    if limit > 0.0 and robot_clearance(costmap, points[0], stop_distance) <= stop_distance:
        # Inside stop_distance and the path leads out: no faster than the creep
        limit = min(limit, creep_speed)
    if age > costmap_timeout:
        return min(limit, crawl), clearance, 'stale'
    return limit, clearance, 'stop' if limit <= 0.0 else 'slow' if limit < max_speed else 'clear'

    GOVERNOR_PARAMS, Costmap, governor_param_problem, obstacle_clearance, path_ahead,

RES = 0.1
LIMITS = dict(max_speed=1.5, slow_distance=2.0, stop_distance=0.35, creep_speed=0.15,
              costmap_timeout=1.0, crawl_speed=0.3)
# delivery-robo's hardware.yaml (TDM-34)
ROBOT = {**LIMITS, 'max_speed': 1.0, 'stop_distance': 0.2}


def corridor_tdm32(half_width=1.5, inscribed=0.32, length=20.0):
    """A straight corridor along +x through y = 0, in odom with its corner at (-5, -5): walls
    lethal, the inscribed band inside them 99, free in between."""
    h, w = int(10 / RES), int(length / RES)
    y = -5 + (np.arange(h) + 0.5) * RES
    cells = np.zeros((h, w), dtype=np.int8)
    cells[np.abs(y) >= half_width - inscribed, :] = 99
    cells[np.abs(y) >= half_width, :] = 100
    return Costmap(cells, RES, (-5.0, -5.0), 'odom')


def add_box_tdm32(costmap, cx, cy, size=0.6, inscribed=0.32):
    """Mark a square box lethal and the band round it inscribed (as a square, close enough)."""
    ox, oy = costmap.origin
    h, w = costmap.cells.shape
    x = ox + (np.arange(w) + 0.5) * RES
    y = oy + (np.arange(h) + 0.5) * RES
    dx, dy = np.abs(x[None, :] - cx), np.abs(y[:, None] - cy)
    cells = costmap.cells.copy()
    cells[(dx <= size / 2 + inscribed) & (dy <= size / 2 + inscribed)] = 99
    cells[(dx <= size / 2) & (dy <= size / 2)] = 100
    return costmap._replace(cells=cells)


def straight_path_tdm32(x0=0.0, x1=12.0):
    xy = np.column_stack((np.arange(x0, x1 + 1e-9, 0.1), np.zeros(int(round((x1 - x0) / 0.1)) + 1)))
    return xy, np.concatenate(([0.0], np.cumsum(np.linalg.norm(np.diff(xy, axis=0), axis=1))))


def ahead_tdm32(x, path=None, y=0.0):
    """The robot at (x, y) and the next 3 m of a path sampled every 0.1 m from x = 0."""
    xy, s = path if path is not None else straight_path_tdm32()
    return path_ahead((x, y), xy, s, max(int(x / 0.1) - 5, 0), 3.0)

def costmap_speed_limit(self, state, path_xy, path_s):
    """The fastest the costmap lets the robot go on from `state` along the path."""
    if not self.use_costmap:
        return self.max_speed
    age = costmap_pose = None
    if self.costmap is not None:
        age = (self.get_clock().now() - self.costmap_arrival).nanoseconds * 1e-9
        costmap_pose = {'map': (0.0, 0.0, 0.0),
                        self._odom_frame: self._map_to_odom}.get(self.costmap.frame)
    points = path_ahead(state, path_xy, path_s, self.progress_idx, self.clearance_lookahead)
    limit, clearance, status = speed_limit(
        self.costmap_remembered, age, points, costmap_pose, self.max_speed, self.slow_distance,
        self.stop_distance, self.obstacle_creep_speed, self.costmap_timeout, self.crawl_speed)

    if status in ('missing', 'unplaced', 'stale'):
        problem = {
            'missing': f'no costmap on {self.costmap_subscription.topic_name} yet',
            'unplaced': f'costmap in frame "{self.costmap.frame if self.costmap else ""}", '
                        f'neither map nor {self._odom_frame}',
            'stale': f'costmap {age:.1f} s old',
        }[status]
        self.get_logger().warning(f'{problem}: speed capped at {limit:.2f} m/s',
                                  throttle_duration_sec=5.0)
    elif status == 'stop' and self._speed_status != 'stop':
        self.get_logger().info(
            f'Obstacle {clearance:.2f} m away near the path ahead: stopped until it clears')
    elif status != 'stop' and self._speed_status == 'stop':
        self.get_logger().info('Path ahead clear: driving on')
    self._speed_status = status
    return limit

*** End of Path
The termination check stops the robot once it is within =xy_goal_tolerance= of the end of the path. Before this taper, it got there at full speed. At 1.5 m/s the zero command came too late: the robot coasted ~0.4 m and stopped 0.20-0.28 m past the end by its own estimate (TDM-25). So the target speed is now capped by the arc length left to the end of the path, $v \le \sqrt{2 a d}$ with $a$ = =goal_decel=. That is the speed from which braking at $a$ stops the robot exactly at the end. With 0.8 m/s² it starts braking 1.4 m out and reaches the tolerance circle at 0.63 m/s, where the zero command takes over. =goal_creep_speed= is a floor: when the robot reaches the end but is still outside the tolerance (off to the side, or at the wrong heading), it keeps moving instead of stalling just short.

The follower can't tell a path that ends at the goal from one that local_planner will replace in half a second, so every path gets the taper. That costs nothing: local_planner aims ~12 m ahead, so its intermediate paths end well beyond the 1.4 m where the taper starts. Only the last paths, which end at the goal itself, get close enough. The taper and the obstacle limit are separate caps on the same target, and the lower one wins.

Measured in the sim (TDM-37: three runs to node 1282043935 with the WGS84 EKF, ground truth):
- The zero command now comes at 0.56-0.60 m/s. The robot rolls 0.06-0.07 m after it.
- It stops 0.14-0.16 m short of the node, almost all of it along the path.
- Without the taper it stopped 0.36-0.43 m past the node.
What is left is the goal tolerance: the robot stops as soon as it is inside 0.25 m.

def end_taper_speed(remaining, decel, creep_speed):
    """The fastest the robot can go `remaining` m (arc length) before the end of the path and
    still stop there braking at `decel`: sqrt(2 decel remaining), but never below creep_speed."""
    return max(creep_speed, math.sqrt(2.0 * decel * max(remaining, 0.0)))

*** Reference Trajectory
The planned path arrives as a sequence of poses, but the headings stored on those poses are not usable directly: waypoints can be clustered arbitrarily close together, and a pair of near-coincident points yields a meaningless tangent. Headings are therefore recomputed here from the geometry of the path itself, after discarding waypoints that sit closer than ~MIN_DIST~ to their predecessor.

Each waypoint is also assigned an arc length $s$ along the path, which is what the reference is later interpolated against.

#+begin_src python :tangle ../src/autonomy/autonomy/utils/reference_trajectory.py
import numpy as np

MIN_DIST = 0.1

def process_path(path_msg):
    raw_x = [pose.pose.position.x for pose in path_msg.poses]
    raw_y = [pose.pose.position.y for pose in path_msg.poses]
    raw_xy = np.column_stack((raw_x, raw_y))

    if len(raw_xy) < 2:
        return raw_xy, np.zeros(len(raw_xy)), np.zeros(len(raw_xy))

    filtered_xy = [raw_xy[0]]
    for pt in raw_xy[1:]:
        if np.linalg.norm(pt - filtered_xy[-1]) >= MIN_DIST:
            filtered_xy.append(pt)

    # The goal must survive filtering even if it falls close to its predecessor
    if np.linalg.norm(raw_xy[-1] - filtered_xy[-1]) > 0.01:
        filtered_xy.append(raw_xy[-1])

    filtered_xy = np.array(filtered_xy)

    diffs = np.diff(filtered_xy, axis=0)
    dists = np.linalg.norm(diffs, axis=1)
    path_s = np.concatenate(([0.0], np.cumsum(dists)))

    path_theta = np.arctan2(diffs[:, 1], diffs[:, 0])

    # The final point has no successor, so it inherits the preceding heading
    path_theta = np.append(path_theta, path_theta[-1])

    # Unwrapped so that interpolation does not jump across the pi boundary
    path_theta_unwrapped = np.unwrap(path_theta)

    return filtered_xy, path_theta_unwrapped, path_s

def get_local_reference(state, path_xy, path_theta_unwrapped, path_s, T, dt, v_target, progress_idx=0):
    x, y = state[0], state[1]
    
    search_start = progress_idx
    search_end = min(len(path_s), progress_idx + 50) 
    
    distances_to_path = np.linalg.norm(
        path_xy[search_start:search_end] - np.array([x, y]), axis=1
    )
    closest_idx = search_start + np.argmin(distances_to_path)
    
    # NEW: Calculate continuous projection to prevent the carrot from lagging
    p_closest = path_xy[closest_idx]
    if closest_idx < len(path_xy) - 1:
        p_next = path_xy[closest_idx + 1]
        vec_path = p_next - p_closest
        vec_robot = np.array([x, y]) - p_closest
        
        path_len2 = np.dot(vec_path, vec_path)
        if path_len2 > 1e-5:
            # Vector projection to find exact fractional progress 't'
            t = np.dot(vec_robot, vec_path) / path_len2
            t = np.clip(t, 0.0, 1.0)
            s_current = path_s[closest_idx] + t * np.linalg.norm(vec_path)
        else:
            s_current = path_s[closest_idx]
    else:
        s_current = path_s[closest_idx]
        
    # Add lookahead so the horizon starts decisively in front of the axle
    lookahead_dist = 0.5
    s_target = s_current + lookahead_dist + np.arange(T) * (v_target * dt)
    
    # Linearly interpolate x, y, and unwrapped theta at the target 's' values
    ref_x = np.interp(s_target, path_s, path_xy[:, 0])
    ref_y = np.interp(s_target, path_s, path_xy[:, 1])
    ref_theta_unwrapped = np.interp(s_target, path_s, path_theta_unwrapped)
    
    # Re-wrap theta back to [-pi, pi]
    ref_theta = (ref_theta_unwrapped + np.pi) % (2 * np.pi) - np.pi
    
    return np.stack([ref_x, ref_y, ref_theta], axis=-1), closest_idx

*** MPPI
See [[id:4f1361c2-eb14-466a-a692-45fbd9c34e47][Model Predictive Path Integral]].

The step takes its speed and steering bounds as arguments. The controller passes =[min_speed, -max_steer_rad]= to =[v_target, max_steer_rad]=, the same bounds it clips the result to, so MPPI no longer spends samples on speeds the controller would clip anyway. Before, the bounds were fixed at -0.5 to 1.5 m/s, and with the target lowered to 0.3 m/s near an obstacle most of the samples were faster than anything that could be sent. They are arrays of a fixed shape, so a new value never makes jax compile the step again.

Each rollout also pays for the costmap cells it drives through (see [[*Obstacle Cost][Obstacle Cost]]). That cost is added on top of the path-tracking costs, so ~ell~ and ~phi~ themselves are unchanged.

The rollouts drive the controller's =Vehicle= (see [[*Parameters][Parameters]]), passed in for the same reason as the bounds. Without one they drive the sim car. ~ell~ needs it too: it recovers the current steering angle from the yaw rate with the wheelbase.

def mppi_step(key, x0, U_nominal, ref_traj, v_target, lower_bounds, upper_bounds, window,
              obstacle_steps, vehicle=SIM_VEHICLE):
    """
    x0: (STATE_DIMENSION,)
    U_nominal: (T, INPUT_DIMENSION)
    ref_traj: (T, 3) containing [x, y, theta]
    lower_bounds, upper_bounds: (INPUT_DIMENSION,) [v, delta] the samples are clipped to
    window: CostWindow, the costmap round the robot (free_window() for none)
    obstacle_steps: int32, the obstacle cost counts for the states before this step (T + 1: all
        of them, the final state too)
    vehicle: Vehicle, the car the rollouts drive
    """
    T = U_nominal.shape[0]
    ref_costs = jax.vmap(cell_cost, in_axes=(0, None))(ref_traj, window)

    def obstacles(state):
        return obstacle_cost(state, window, ref_traj, ref_costs)

    # Create closures that inject ref_traj into the unbatched functions
    def ell_closure(state, action, t):
        return (ell(state, action, t, ref_traj, v_target, vehicle)
                + jnp.where(t < obstacle_steps, obstacles(state), 0.0))

    def phi_closure(state):
        return phi(state, ref_traj) + jnp.where(T < obstacle_steps, obstacles(state), 0.0)

    # Vmap the closures over the batch dimension (axis 0 for state and action).
    # t is a scalar, so we use None for its axis.
    batch_ell = jax.vmap(ell_closure, in_axes=(0, 0, None))
    batch_phi = jax.vmap(phi_closure, in_axes=(0,))

    return mppi(
        key=key, 
        f=lambda states, actions: batch_dynamics(states, actions, DT, vehicle),
        x0=x0, 
        U=U_nominal, 
        phi=batch_phi, 
        ell=batch_ell,
        sigma=sigma,
        K=3000,
        lam=30.0,
        lower_bounds=lower_bounds,
        upper_bounds=upper_bounds,
    )

def ell(state, action, t, ref_traj_window, v_target, vehicle):
    x, y, theta, v, omega, b_omega = state
    v_cmd, raw_delta = action
    delta_cmd = jnp.clip(raw_delta, -vehicle.max_steer_rad, vehicle.max_steer_rad)
    
    target_state = ref_traj_window[t]
    x_ref, y_ref, theta_ref = target_state[0], target_state[1], target_state[2]
    
    dx = x - x_ref
    dy = y - y_ref
    
    cte = -dx * jnp.sin(theta_ref) + dy * jnp.cos(theta_ref)

    theta_error = theta - theta_ref
    theta_error = (theta_error + jnp.pi) % (2 * jnp.pi) - jnp.pi
    v_error = v - v_target

    # Pseudo-Huber, so a large excursion does not dominate every other term
    cte_cost = jnp.sqrt(cte**2 + 0.05) - jnp.sqrt(0.05)

    # Penalising the change in steering angle rather than its magnitude lets the
    # robot hold a steady curve for free while still damping rapid reversals
    safe_v = jnp.where(jnp.abs(v) < 1e-5, jnp.sign(v + 1e-10) * 1e-5, v)
    current_delta = jnp.arctan((omega * vehicle.wheelbase) / safe_v)
    steer_effort_cost = (delta_cmd - current_delta)**2

    w_cte = 90.0
    w_theta = 30.0
    w_steer_effort = 25.0
    w_omega = 5.0
    w_v = 20.0

    return (w_cte * cte_cost +
            w_theta * (theta_error**2) +
            w_steer_effort * steer_effort_cost +
            w_omega * (omega**2) +
            w_v * (v_error**2))
#+end_src

def phi(state, ref_traj_window):
    x, y, theta, v, omega, b_omega = state

    target_state = ref_traj_window[-1]
    x_ref, y_ref, theta_ref = target_state[0], target_state[1], target_state[2]

    dx = x - x_ref
    dy = y - y_ref

    cte = -dx * jnp.sin(theta_ref) + dy * jnp.cos(theta_ref)

    theta_error = theta - theta_ref
    theta_error = (theta_error + jnp.pi) % (2 * jnp.pi) - jnp.pi

    # Only lateral and heading error are penalised. Charging for distance along
    # the path would make slowing down for a sharp corner prohibitively costly.
    w_cte_term = 200.0
    w_theta_term = 50.0

    return w_cte_term * (cte**2) + w_theta_term * (theta_error**2)

**** Obstacle Cost
The speed limit ([[*Obstacle Speed Limit][Obstacle Speed Limit]]) slows the robot down near obstacles, but on its own it still drives the path it was given. local_planner replans only twice a second, and its paths pass the marked face of a box closely and swing back towards the centreline behind it. MPPI runs at 10 Hz and decides where the robot actually goes, so each state of a rollout now also pays for the costmap cell it is in:

- $w_{obstacle} \frac{|v|}{1.5} \left( (c/100)^2 - (c_{ref}/100)^2 \right)$, with $c$ the cost of its cell, $c_{ref}$ the cost at the nearest reference point and $v$ its speed. Following the path costs nothing. Moving off it towards an obstacle costs more and more, and moving away from one earns as much. Nav2's inflation falls off with the distance to the nearest obstacle, so a path that cuts close to an obstacle is left for the middle of the gap: gently far out, hard close in.
- =LETHAL_PENALTY= per step in a cell of 99 (inscribed) or 100 (lethal). A robot centred in such a cell touches the obstacle (see [[*Obstacle Speed Limit][Obstacle Speed Limit]]), so a rollout that goes there loses to every rollout that does not. A path straight through an obstacle is left too, or, when there is no way round, the robot stops in front of it.

The first version charged $w_{obstacle} (c/100)^2$ per step: the cost of the cell itself, every step. It worked at full speed in a synthetic corridor but refused gaps in the sim. With =stop_distance= 0.2 the speed limit slowed the robot to a few tenths of a m/s in front of the centred box. In its 5 s a rollout then covers only 2 m or so. It sees the cost of driving into the gap, but not the free corridor behind the box. Every rollout that drove on paid for the gap, and one that stood still or backed off paid less. MPPI stopped 0.5 m short of the box and reversed at 0.5 m/s, on and off, for 16 s. TDM-32's speed limit alone had squeezed through. Two changes fixed it:
- The cost is relative to the path. A rollout that keeps to the path pays nothing, however close the path runs to an obstacle. Whether to drive on or stop is left to the path tracking and the speed limit. The obstacle cost only decides where across the corridor the robot drives, plus the penalty.
- It is charged per metre, not per step: scaled by $|v|/1.5$, so the weights are unchanged at 1.5 m/s. A rollout that slows down beside an obstacle neither pays nor earns more for lingering there.

States behind the first reference point are not compared at all. The reference starts 0.5 m ahead of the robot, so the first reference point is nearest to any state behind it. With that point next to a box, a rollout backing away would earn the difference.

The cost is looked up at the robot's centre, like the speed limit's clearance, so the costmap brings the footprint along. The front and rear corners reach up to 0.19 m further than the inscribed radius. The inflation term keeps some room for them, and the speed limit covers the front.

Some numbers for the weights at 1.5 m/s, with inflation radius 1.8 m and scaling 2.0 (=nav2_local.yaml=):
- Beside a box, moving from 0.33 m off its side (just outside the inscribed band) to 0.6 m off it earns about 190 per step. Tracking 0.27 m off the path costs 11 per step.
- In a 3 m corridor, a path 0.5 m off the centreline is followed about 0.2 m closer to the middle.
- When the path runs straight through a box in the middle of the corridor, keeping to the middle of the gap beside it costs 63 per step in tracking and earns 210 against the box's cells on the path. Driving through the box costs the penalty, 1000 per step.
No amount of tracking error is worth an inscribed cell. With =lam= 30, a rollout that costs 30 more in total already carries 1/e of the weight.

=W_OBSTACLE= 100 was too weak. The box tests below drive the dynamics model along a path through or past a box in the middle of a 3 m corridor. With 100, MPPI kept the side of the footprint 0.14 m from the box when the path ran straight through it. When the path cut 0.02 m into the inscribed band it kept 0.20 m at 1.5 m/s and 0.06 m at 0.4 m/s. With 300 it kept 0.23, 0.28 and 0.16 m. The middle of the gap allows 0.285 m. In the empty corridor neither weight moved the robot more than 0.03 m off the path.

Unknown cells (-1, off the map) and anything outside the window cost nothing, like free cells. An all-free window therefore adds exactly zero, and MPPI tracks the path as it did before. The controller passes an all-free window when =use_costmap= is false, before a costmap has arrived, when the latest one is older than =costmap_timeout= (the speed limit then caps the speed at =crawl_speed=), and when its frame is neither map nor odom.

jax compiles =mppi_step= for the shapes of its arguments. Nav2's costmap is 400 x 400 cells now, but its size is a parameter. So the controller passes a window of a fixed 200 x 200 cells, cut round the robot from the latest costmap: 20 x 20 m at 0.1 m. A rollout covers at most 7.5 m (5 s at 1.5 m/s), so it stays inside. The window stays in the costmap's frame (odom), with the cached map->odom. The rollout states are in map, and the jitted cost moves each one into the window's frame: a shift and a rotation per state.

Rollouts do not know that the robot stops at the end of the path. The reference stops there, but the rollouts drive on at about the target speed. In the first sim run (with the first version of the cost) the goal node sat 1.4 m in front of the end wall of a dead end. The rollouts that ran on into that wall made MPPI crawl the last 3 m at 0.6 down to 0.05 m/s, where TDM-37 had arrived at 0.6 m/s. In the synthetic test below it stalled 0.35 m short, outside the goal tolerance. The termination check stops the robot at the end of the path, so what a rollout does after that never happens. The obstacle cost therefore counts only for the first =charged_steps= states of each rollout. Those are the states before a rollout at the target speed, the fastest MPPI samples, could reach the end of the path. Far from the end of the path that is the whole horizon.

Measured in the sim (TDM-33: TDM-25's route to node 1282043935 with a 0.6 m box, both the speed limit and the obstacle cost on; clearance between the footprint and the box by ground truth):
- No box: the drive is unchanged. No slowdowns, the zero command at 0.59 m/s, 0.15 m short of the node.
- Box in the middle of the corridor: the speed limit stops the robot 0.28-0.32 m from it, goal kept, as before. It drives on once the box is removed.
- The same with =stop_distance= 0.2, two runs. In one the robot went through the gap at 0.3-0.7 m/s with one half-second stop. It came within 0.22 m of the box, on the swing back behind it: the rear corner, which the cost does not see (TDM-32: 0.24 m with the speed limit alone). In the other, local_planner's path ran 0.83 m off the centreline, 0.2 m from the box's inscribed band, and the speed limit stopped the robot 0.27 m from the box until the box was removed.
- Box 0.45 m off-centre: no stop, through the middle of the wide gap at 0.2 m/s and up, 0.44 m from the box. TDM-32 measured 0.49 m with the speed limit alone, a little nearer the wall, and TDM-25 0.36 m with neither.
MPPI only avoids what the costmap shows. Here local_planner's paths already went round the marked box, so the clearances are within run-to-run spread of the speed limit's alone. The cost earns its keep where the path cuts close to an obstacle or runs through one that was seen late, as in the tests below. A step takes 21 ms on the laptop (=bench_mppi=), against 15 ms without the obstacle cost. Most of the difference is finding the nearest reference point for every state.

#+name: cost_window
#+begin_src python
# Cells per side of the costmap window MPPI checks rollouts against: 20 m at 0.1 m, centred on the
# robot. A fixed size, so jax compiles mppi_step only once.
WINDOW_CELLS = 200


class CostWindow(NamedTuple):
    cells: np.ndarray        # (WINDOW_CELLS, WINDOW_CELLS) float32 costmap values 0-100; row = y
    origin: np.ndarray       # (2,) float32: outer corner of cell [0, 0], in the costmap's frame
    resolution: np.ndarray   # () float32: m per cell
    frame_pose: np.ndarray   # (3,) float32: the costmap frame's pose in map, (x, y, yaw)


def free_window():
    """A window with nothing in it: the obstacle cost is then exactly zero everywhere."""
    return CostWindow(np.zeros((WINDOW_CELLS, WINDOW_CELLS), dtype=np.float32),
                      np.zeros(2, dtype=np.float32), np.float32(0.1), np.zeros(3, dtype=np.float32))


def crop_window(costmap, centre, frame_pose):
    """The WINDOW_CELLS-square part of `costmap` (a costmap_speed.Costmap) round `centre` (map
    frame). frame_pose is the costmap frame's pose in map, (x, y, yaw). Unknown cells (-1) and
    cells off the costmap come out free (0)."""
    res = costmap.resolution
    ox, oy = costmap.origin
    (cx, cy), = to_frame(np.reshape(np.asarray(centre, dtype=float)[:2], (1, 2)), frame_pose)
    c0 = math.floor((cx - ox) / res) - WINDOW_CELLS // 2
    r0 = math.floor((cy - oy) / res) - WINDOW_CELLS // 2
    height, width = costmap.cells.shape
    cells = np.zeros((WINDOW_CELLS, WINDOW_CELLS), dtype=np.float32)
    rs, re = max(r0, 0), min(r0 + WINDOW_CELLS, height)
    cs, ce = max(c0, 0), min(c0 + WINDOW_CELLS, width)
    if rs < re and cs < ce:
        cells[rs - r0:re - r0, cs - c0:ce - c0] = np.maximum(costmap.cells[rs:re, cs:ce], 0)
    return CostWindow(cells, np.array([ox + c0 * res, oy + r0 * res], dtype=np.float32),
                      np.float32(res), np.asarray(frame_pose, dtype=np.float32))
#+end_src

#+name: obstacle_cost
#+begin_src python
W_OBSTACLE = 300.0        # times the change in (cost / 100)^2 from the path, per step at CRUISE_SPEED
CRUISE_SPEED = 1.5        # m/s; slower states pay in proportion (per metre)
LETHAL_PENALTY = 1000.0   # per step in an inscribed (99) or lethal (100) cell

def cell_cost(state, window):
    """The costmap value (0-100) under the robot's centre, state in map; 0 off the window."""
    fx, fy, fyaw = window.frame_pose[0], window.frame_pose[1], window.frame_pose[2]
    c, s = jnp.cos(fyaw), jnp.sin(fyaw)
    dx, dy = state[0] - fx, state[1] - fy
    # Into the costmap's frame, then to a cell
    col = jnp.floor((c * dx + s * dy - window.origin[0]) / window.resolution).astype(jnp.int32)
    row = jnp.floor((c * dy - s * dx - window.origin[1]) / window.resolution).astype(jnp.int32)
    cells = jnp.asarray(window.cells)
    rows, cols = cells.shape
    inside = (row >= 0) & (row < rows) & (col >= 0) & (col < cols)
    return jnp.where(inside, cells[jnp.clip(row, 0, rows - 1), jnp.clip(col, 0, cols - 1)], 0.0)


def obstacle_cost(state, window, ref_traj, ref_costs):
    """What one state (map frame) pays for the costmap cell under the robot's centre: the change
    in W_OBSTACLE (cost / 100)^2 from the nearest reference point (ref_costs holds their
    cell_cost; nothing behind the first one), plus LETHAL_PENALTY in an inscribed or lethal cell."""
    cost = cell_cost(state, window)
    nearest = jnp.argmin((ref_traj[:, 0] - state[0])**2 + (ref_traj[:, 1] - state[1])**2)
    x0, y0, theta0 = ref_traj[0, 0], ref_traj[0, 1], ref_traj[0, 2]
    along = (state[0] - x0) * jnp.cos(theta0) + (state[1] - y0) * jnp.sin(theta0)
    behind = (nearest == 0) & (along < 0.0)
    change = jnp.where(behind, 0.0, (cost / 100.0)**2 - (ref_costs[nearest] / 100.0)**2)
    # Per metre driven, not per step: lingering beside the path neither pays nor earns
    per_metre = jnp.abs(state[3]) / CRUISE_SPEED
    return W_OBSTACLE * per_metre * change + jnp.where(cost >= INSCRIBED, LETHAL_PENALTY, 0.0)


def charged_steps(remaining, v_target, horizon, dt=DT):
    """How many states of the horizon the obstacle cost counts for: those before a rollout at
    v_target could reach the end of the path, `remaining` m (arc length) ahead. horizon + 1 (every
    state, the final one too) when the end is out of reach."""
    if v_target <= 0.0:
        return np.int32(horizon + 1)
    return np.int32(min(max(math.ceil(remaining / (v_target * dt)), 0), horizon + 1))
#+end_src

Every tick the controller cuts the window round the state it optimises from, out of the latest costmap. Cutting it takes about 0.05 ms.

def mppi_costmap_window(self, state):
    """The costmap round `state` for MPPI's obstacle cost, or an all-free window when the
    costmap is off, missing, stale or in a frame the controller cannot place."""
    if not self.use_costmap or self.costmap is None:
        return self._free_window
    age = (self.get_clock().now() - self.costmap_arrival).nanoseconds * 1e-9
    frame_pose = {'map': (0.0, 0.0, 0.0), self._odom_frame: self._map_to_odom}.get(self.costmap.frame)
    if age > self.costmap_timeout or frame_pose is None:
        return self._free_window
    return crop_window(self.costmap, state, frame_pose)

def cell_centre_tdm33(row, col):
    return -20.0 + (col + 0.5) * RES, -20.0 + (row + 0.5) * RES


def box_costmap_tdm33(bx, by, size=0.6, half_width=None, end_wall=None, inscribed=0.32, radius=1.8,
                      scaling=2.0):
    """One square box in odom, optionally in a corridor along x (walls beyond |y| = half_width)
    that may end in a wall at x = end_wall, inflated like Nav2: 100 inside, 99 within the
    inscribed radius, then 252 exp(-scaling (d - inscribed)) out to the radius, translated to
    1-98 as in Nav2's OccupancyGrid."""
    x = -20.0 + (np.arange(400) + 0.5) * RES
    dx = np.maximum(np.abs(x[None, :] - bx) - size / 2, 0.0)
    dy = np.maximum(np.abs(x[:, None] - by) - size / 2, 0.0)
    d = np.hypot(dx, dy)
    if half_width is not None:
        d = np.minimum(d, np.maximum(half_width - np.abs(x[:, None]), 0.0))
    if end_wall is not None:
        d = np.minimum(d, np.maximum(end_wall - x[None, :], 0.0))
    raw = np.floor(252.0 * np.exp(-scaling * (d - inscribed)))
    cells = np.where(d <= radius, 1 + (97 * (raw - 1)) // 251, 0)
    cells = np.where(d <= inscribed, 99, cells)
    return costmap_tdm33(np.where(d == 0.0, 100, cells))


def state_tdm33(x, y, v=CRUISE_SPEED):
    """A state (map frame) with the robot at odom (x, y), driving at v."""
    return jnp.array([*to_map_tdm33(x, y), 0.0, v, 0.0, 0.0])


def cell_at_tdm33(window, x, y):
    """cell_cost of a robot at odom (x, y)."""
    return float(cell_cost(state_tdm33(x, y), window))


def obstacle_cost_tdm33(window, x, y, ref_odom, v=CRUISE_SPEED):
    """obstacle_cost of a robot at odom (x, y), driving at v, against a reference through the
    odom points ref_odom (heading along odom +x)."""
    ref = jnp.array([[*to_map_tdm33(rx, ry), MAP_TO_ODOM_TDM33[2]] for rx, ry in ref_odom])
    ref_costs = jax.vmap(cell_cost, in_axes=(0, None))(ref, window)
    return float(obstacle_cost(state_tdm33(x, y, v), window, ref, ref_costs))

def test_cell_lookup():
    cells = np.zeros((400, 400))
    probes = {(210, 205): 50, (210, 206): 98, (215, 190): 99, (170, 202): 100, (230, 230): -1,
              (200, 325): 100}

        cells[cell] = value
    window = crop_window(costmap_tdm33(cells), to_map_tdm33(0.0, 0.0), MAP_TO_ODOM_TDM33)

def test_cost_is_the_change_from_the_nearest_reference_point_plus_the_penalty():
    cells = np.zeros((400, 400))
    cells[200, 210:213] = (40, 60, 99)      # odom (1.05, 0.05), (1.15, 0.05), (1.25, 0.05)
    window = crop_window(costmap_tdm33(cells), to_map_tdm33(0.0, 0.0), MAP_TO_ODOM_TDM33)
    ref = [(0.05, 0.05), (1.05, 0.05), (2.05, 0.05)]    # through the 40 cell
    assert obstacle_cost_tdm33(window, 1.05, 0.05, ref) == pytest.approx(0.0)  # on the path: nothing
    assert obstacle_cost_tdm33(window, 1.15, 0.05, ref) == pytest.approx(W_OBSTACLE * (0.6**2 - 0.4**2))
    assert obstacle_cost_tdm33(window, 1.25, 0.05, ref) == pytest.approx(
        W_OBSTACLE * (0.99**2 - 0.4**2) + LETHAL_PENALTY)
    assert obstacle_cost_tdm33(window, 1.05, 0.35, ref) == pytest.approx(-W_OBSTACLE * 0.4**2)  # off it
    assert obstacle_cost_tdm33(window, 0.05, 0.35, ref) == 0.0      # free, and so is the path there
    # Per metre: half the speed, half the cost per step. Standing still, only the penalty is left.
    assert obstacle_cost_tdm33(window, 1.15, 0.05, ref, v=CRUISE_SPEED / 2) == pytest.approx(
        W_OBSTACLE * (0.6**2 - 0.4**2) / 2)
    assert obstacle_cost_tdm33(window, 1.25, 0.05, ref, v=0.0) == pytest.approx(LETHAL_PENALTY)
    # Behind the first reference point (where the robot is now) nothing is compared
    assert obstacle_cost_tdm33(window, 1.15, 0.05, [(1.6, 0.05), (2.05, 0.05)]) == 0.0

def drive_tdm33(costmap, ticks=60, path_end=20.0, cut=True, v_cap=1.5, bend=None):
    """Follow a path along odom +x from (0, 0) to (path_end, 0) for up to `ticks` 10 Hz control
    ticks: MPPI, the end taper and the termination check as the controller runs them (default
    parameters), the dynamics model as the robot. The path is straight, or with bend=(x, dy) it
    swings out by dy round x and back over 5 m, like local_planner's paths round a box.
    cut=False charges the obstacle cost over the whole horizon; v_cap caps the target speed like
    the obstacle speed limit. Returns the track in odom and the speeds sent."""
    x = np.arange(0.0, path_end + 1e-9, 0.1)
    y = np.zeros_like(x)
    if bend is not None:
        near = np.abs(x - bend[0]) < 2.5
        y[near] = bend[1] * 0.5 * (1.0 + np.cos(np.pi * (x[near] - bend[0]) / 2.5))
    path_xy = np.array([to_map_tdm33(px, py) for px, py in zip(x, y)])
    step = np.diff(path_xy, axis=0)
    path_theta = np.unwrap(np.append(np.arctan2(step[:, 1], step[:, 0]), np.arctan2(*step[-1, ::-1])))
    path_s = np.concatenate(([0.0], np.cumsum(np.linalg.norm(step, axis=1))))
    state = np.array([*path_xy[0], MAP_TO_ODOM_TDM33[2], 1.5, 0.0, 0.0])
    U = jnp.zeros((50, INPUT_DIMENSION)).at[:, 0].set(1.5)
    key, progress, track, speeds = jax.random.PRNGKey(0), 0, [], []
    for _ in range(ticks):
        if np.hypot(*(state[:2] - path_xy[-1])) < 0.25:
            break
        remaining = path_s[-1] - path_progress(state, path_xy, path_s, progress)
        v_target = min(v_cap, end_taper_speed(remaining, 0.8, 0.15))
        lower, upper = jnp.array([-0.5, -0.6]), jnp.array([v_target, 0.6])
        ref, progress = get_local_reference(state, path_xy, path_theta, path_s, 50, 0.1,
                                            v_target=v_target, progress_idx=progress)
        window = free_window() if costmap is None else crop_window(costmap, state, MAP_TO_ODOM_TDM33)
        steps = charged_steps(remaining, v_target, 50) if cut else np.int32(51)
        key, sub = jax.random.split(key)
        U = jnp.clip(mppi_step(sub, state, jnp.clip(U, lower, upper), jnp.array(ref), v_target,
                               lower, upper, window, steps), lower, upper)
        state = np.asarray(dynamics_model(state, U[0], dt=0.1), dtype=float)
        speeds.append(float(U[0, 0]))
        U = jnp.roll(U, -1, axis=0).at[-1].set(U[-1])
        track.append(to_frame(state[None, :2], MAP_TO_ODOM_TDM33)[0])
    return np.array(track), np.array(speeds)


def box_gap_tdm33(track, bx, by, size=0.6):
    """Closest approach of the robot's centre to the box's edge."""
    gap = np.maximum(np.abs(track - (bx, by)) - size / 2, 0.0)
    return float(np.hypot(gap[:, 0], gap[:, 1]).min())

import sys
import csv
import math
import os
import time
from datetime import datetime, timezone

import rclpy
from rclpy.node import Node
from rclpy.action import ActionClient
from shared_types.action import ComputePath, FollowPath

class BehaviorNode(Node):
    def __init__(self):
        super().__init__('behavior_node')
        self.planner_client = ActionClient(self, ComputePath, '/compute_shortest_path')
        self.controller_client = ActionClient(self, FollowPath, '/follow_path')
        self.metrics_path = os.environ.get(
            'DELIVERY_METRICS_PATH',
            'delivery_metrics.csv',
        )

    def path_length(self, path):
        total = 0.0

        for first, second in zip(path.poses, path.poses[1:]):
            dx = second.pose.position.x - first.pose.position.x
            dy = second.pose.position.y - first.pose.position.y
            total += math.hypot(dx, dy)

        return total

    def record_metrics(
        self,
        target_node_id,
        predicted_seconds,
        actual_seconds,
        success,
    ):
        file_exists = os.path.exists(self.metrics_path)

        with open(self.metrics_path, 'a', newline='') as file:
            writer = csv.writer(file)

            if not file_exists:
                writer.writerow([
                    'timestamp',
                    'goal_node_id',
                    'predicted_seconds',
                    'actual_seconds',
                    'error_seconds',
                    'percent_error',
                    'success',
                ])

            error_seconds = actual_seconds - predicted_seconds
            percent_error = (
                error_seconds / predicted_seconds * 100
                if predicted_seconds > 0
                else 0.0
            )

            writer.writerow([
                datetime.now(timezone.utc).isoformat(),
                target_node_id,
                f'{predicted_seconds:.3f}',
                f'{actual_seconds:.3f}',
                f'{error_seconds:.3f}',
                f'{percent_error:.2f}',
                success,
            ])

    def plan_and_move(self, target_node_id):
        # Block and wait for the path
        self.get_logger().info('Connecting to planner...')
        self.planner_client.wait_for_server()

        goal_msg = ComputePath.Goal(goal_node_id=target_node_id)
        
        send_goal_future = self.planner_client.send_goal_async(goal_msg)
        rclpy.spin_until_future_complete(self, send_goal_future)
        goal_handle = send_goal_future.result()

        if not goal_handle.accepted:
            self.get_logger().error('Goal rejected.')
            return

        self.get_logger().info('Computing path...')
        result_future = goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)
        
        computed_path = result_future.result().result.path

        # Estimate travel time using the controller's target speed.
        path_distance = self.path_length(computed_path)
        target_speed = 1.5
        predicted_seconds = path_distance / target_speed

        self.get_logger().info(
            f'Predicted travel time: {predicted_seconds:.2f} seconds'
        )

        # Send the path to the controller
        self.get_logger().info('Path received! Connecting to controller...')
        self.controller_client.wait_for_server()

        follow_msg = FollowPath.Goal(path=computed_path)

        start_time = time.perf_counter()

        send_goal_future = self.controller_client.send_goal_async(follow_msg)
        rclpy.spin_until_future_complete(self, send_goal_future)

        controller_goal_handle = send_goal_future.result()

        if not controller_goal_handle.accepted:
            self.get_logger().error('Controller rejected the path.')
            self.record_metrics(
                target_node_id,
                predicted_seconds,
                0.0,
                False,
            )
            return

        result_future = controller_goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)

        actual_seconds = time.perf_counter() - start_time
        controller_result = result_future.result().result
        success = controller_result.success

        self.record_metrics(
            target_node_id,
            predicted_seconds,
            actual_seconds,
            success,
        )

        self.get_logger().info(
            f'Actual travel time: {actual_seconds:.2f} seconds'
        )

def main(args=None):
    # Parse the command line argument
    if len(sys.argv) < 2:
        print("Usage: python3 quick_start.py <target_node_id>")
        sys.exit(1)
        
    try:
        target_id = int(sys.argv[1])
    except ValueError:
        print("Error: target_node_id must be an integer.")
        sys.exit(1)

    rclpy.init(args=args)
    node = BehaviorNode()
    
    # Pass the argument into the sequence
    node.plan_and_move(target_id)
    
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
